SOCMind 1.6.0 extends the investigation workbench with production-oriented SOC operations alongside Wazuh, Elastic and existing SIEM/EDR systems.

## Operations

- Wazuh and Elastic alert ingestion, automatic case creation, source-scoped deduplication and deterministic, explainable correlation with recorded scores/reasons.
- Contextual evidence collection, chronological evidence merging and upward-only automatic priority escalation.
- Advanced case lifecycle with audited transitions, SLA pause/resume, explicit evidence requirements and a unified operational timeline.
- Correlated Alerts displays provider ID, source, rule, severity, priority, timestamp, host, user, process and correlation reasons.

## Evidence and detection engineering

- Working evidence manifests and SHA-256 verification; a changed package is rejected before merging new evidence.
- Immutable local/S3-compatible snapshots with SQLite/PostgreSQL metadata, collector provenance, size and integrity results.
- Governed rule lifecycle from experimental through production and retirement. Validation, replay, false-positive observations and coverage evidence gate human approval; there is no automatic production promotion.

## Identity and security

- Generic OIDC Authorization Code flow with PKCE, state/nonce, verified ID tokens and claim-to-role mapping; local-token and trusted-proxy modes remain available.
- Signed HttpOnly sessions, same-origin mutation checks, HTTPS defaults and environment-supplied secrets.
- Additive legacy alert-ID migrations, unknown-context correlation guards, deterministic eligible-candidate selection and symlink/atomic evidence-write protections.

## Validation

Release publication is gated by Windows and Ubuntu Python 3.11/3.12, Kali Rolling, PostgreSQL 16, built-wheel and real MinIO-over-HTTPS CI jobs on the merged main commit.

Six synthetic SOC exercises cover password spray/account compromise, Office/PowerShell/C2, Linux SSH/privilege escalation, scheduled-task persistence, benign administration and multi-alert correlation.

Measured local Linux results are committed in `docs/validation/production-ops-load-linux.json`: 10k/100k/1M generated events and 100/1k/10k SQLite cases. The 1M-event analysis took 6.037 seconds (8.573 seconds including generation), with process peak RSS 471,716 KiB. At 10k cases the in-process queue API median was 416.55 ms. Eight workers replayed 40 duplicate alerts and wrote 40 notes without duplicate links or recorded errors. These are synthetic measurements, not capacity guarantees.

## Boundaries

- Live Entra ID, Keycloak and Okta tenant certification is deployment-specific; CI verifies the generic protocol and cryptographic behavior. Sessions have bounded expiry but no central per-session revocation/back-channel logout.
- Object artifacts are explicitly registered and limited to 64 MiB. Conditional writes are required; storage/database administrators remain inside the trust boundary. Hashes are not WORM, trusted timestamps or external custody proof. Failed registration may leave an unreferenced object for operator reconciliation.
- The MinIO integration fixture pins upstream commit 7aac2a2c5b7c882e68c1ce017d8256be2feea27f, including the conditional-create fix. Other provider builds require compatibility validation.
- Benchmarks use local SQLite and an in-process API, excluding networking/TLS and PostgreSQL scale testing. No streaming broker or endpoint collection agent is included.
- Scenario data is synthetic. The spray exercise includes targeted brute-force events; it does not establish a dedicated distributed-spray detector.
- Similarity does not identify an attacker. Case closure, escalation and detection promotion remain analyst decisions.
